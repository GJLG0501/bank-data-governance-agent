# Decisiones de consolidación

1. **Paquete pequeño con adaptadores de comandos.** `bank_governance` contiene el runtime reutilizable; `scripts.data_steward_agent` conserva imports y CLI. No se reescriben generadores ni publicadores que ya tienen restricciones probadas.
2. **PostgreSQL y pgvector.** Se conserva almacenamiento y aislamiento actuales. La mejora lexical usa el manifiesto inmutable de 82 documentos; FTS se difiere hasta justificar DDL con medición y ensayo aislado.
3. **LangChain y LangGraph tienen funciones distintas.** LangChain mantiene modelos, herramienta y salida estructurada. LangGraph aporta un grafo mínimo tipado; no añade un LLM coordinador ni especialistas inexistentes.
4. **Proveedores independientes de embeddings.** Ollama es el default; Gemini es opcional y requiere habilitación explícita. No hay fallback cloud ni llamadas remotas durante la consolidación.
5. **Conservar el extractivo.** La evaluación histórica A/B/C encontró límites reales de generación. Refactorizar no implica aceptar otro modelo de datos o modo por defecto.
6. **Contexto estructurado y volátil.** Se guardan temas y período, no hechos previos como evidencia. Cada turno recupera sus propias fuentes. No se añade otra base de memoria.
7. **Afirmaciones atómicas con límites explícitos.** Python comprueba referencias, operaciones tipadas y procedencia. El texto inferido sigue pendiente de revisión semántica; una operación válida no certifica una explicación entera.
8. **Historia conservada.** No se eliminan informes negativos, migraciones, manifiestos, fuentes ni respaldos. Los experimentos anteriores conservan comandos de reproducción, pero la guía central distingue su estado del runtime vigente.
9. **Pruebas de PostgreSQL seleccionadas.** La suite por defecto no habilita servicios. Solo las comprobaciones publicadas de lectura y el conjunto LLM pequeño se permiten sobre la base activa; los tests históricos con DDL/rollback no se ejecutan allí.
10. **Autorización transversal determinista.** `synthetic-mvp-1` decide acceso con contexto emitido por el anfitrión, sin confiar en roles escritos en chat. Se comprueba en entrada, herramienta y recuperación, además del futuro adaptador SQL. LangGraph no es autoridad de permisos. Los contratos tipados no equivalen a credenciales.
11. **Simulación explícita y default deny.** No hay autenticador real. La CLI necesita seleccionar un perfil sintético; no se concede acceso implícito a los experimentos antiguos. Los fixtures autorizados lo declaran explícitamente. `requires_approval` bloquea; no se implementa aprobación ni administración de usuarios.
12. **Cuarto especialista futuro.** Data Governance explicará políticas y preparará solicitudes autorizadas, pero no podrá aprobarlas, emitir roles ni modificar política. Su capacidad se declara pendiente junto con Analyst/Quality; no se construye otro agente generativo.
13. **Privilegios actuales como bloqueo productivo.** La auditoría de lectura encontró superuser/BYPASSRLS/propietario en la credencial de aplicación. Se conserva sin cambios por el alcance autorizado. La sustitución por roles mínimos, vistas y RLS exige diseño revisado y ensayo PostgreSQL aislado antes de producción.
14. **Clasificación y auditoría sin tocar el corpus.** Propuesta de 42 columnas y política documental local, etiquetadas sintéticas. El texto recuperado no degrada sensibilidad. Auditoría tipada, sin payloads y acotada a memoria; no se presenta como cumplimiento normativo ni log durable. Detalle en [security-and-governance.md](security-and-governance.md).
